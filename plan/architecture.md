# Architecture

```
WeatherNext ensemble ─┐
CW3E AR forecast ─────┤
NOAA tides (9414290) ─┤        ┌──────────────── Coordinator agent ────────────────┐
                      ▼        │ reconciles ensemble → P10 / P50 / P90 depth       │
               Forecast agent ─┼─▶ Terrain agent ─▶ Drainage agent ─▶ Hydraulics  │
                      ▲        │ flags disagreement, writes the situation report   │
NOAA Atlas 14 ────────┘        └──────────────┬────────────────────────────────────┘
USGS 3DEP 1 m lidar ──────────────────────────┤
SF sewer / SFPUC flood map ───────────────────┤
                                              ▼
                         depth_grid.json  ──▶  Trace view (web, 3D tiles)
                                          ──▶  Waterline AR (ARCore Geospatial)
```

## Agents (managed, long-running)

| Agent | Input | Output | Notes |
|---|---|---|---|
| **Forecast** | WeatherNext ensemble members for the grid cell; CW3E AR outlook | `rain_scenarios[]`: depth and peak intensity per member, mapped to an Atlas 14 return period | One per watershed; refreshes on each forecast cycle |
| **Terrain** | 1 m DEM tile(s) | `catchment.geojson`, `sinks[]` (bowl polygons with spill elevation and storage volume) | Cached; runs once per neighborhood |
| **Drainage** | Sewer/inlet data, or design-standard estimates | `capacity_mm_per_hr` per sink catchment | Estimates are flagged `assumed` |
| **Hydraulics** | Scenario, sinks and capacity | `depth_grid` per scenario (fill-and-spill) | Code generated by Argon in one run |
| **Coordinator** | All of the above | `situation_report.md`, P10/P50/P90 depth, disagreement flags, alerts | The only agent that writes alerts |

Replay mode: the forecast agent takes **observed** rainfall (e.g. SF downtown gauge hourly data) instead of an ensemble. Everything downstream is identical.

## Data contract: every value carries provenance

```json
{
  "value": 0.42,
  "units": "m",
  "provenance": "official | derived | assumed",
  "source": "USGS 3DEP 1m, tile x/y | NOAA Atlas 14 PFDS | estimate: SF design std",
  "note": "optional, required when provenance = assumed"
}
```

Rendering rule: `official` is drawn solid, `derived` (computed only from official inputs) is solid with a thin outline, and `assumed` is **hatched**. Any depth that depends on an `assumed` input inherits the hatch.

## Fill-and-spill (screening)

1. Fill DEM sinks, and record each sink's spill elevation and storage volume.
2. Runoff volume into each sink = (rain depth − infiltration) × contributing area, minus drainage capacity × storm duration.
3. Fill sinks in topological order; overflow spills to the downstream sink.
4. Depth = water surface − ground elevation, clipped at 0.
5. Coastal toggle: raise the boundary water level to MHHW + king-tide offset + scenario surge. Only cells hydraulically connected to open water get flooded (a connectivity check, not a pure bathtub).

What this ignores, as stated in the app's Limitations panel: flow timing and velocity, pipe surcharge dynamics, and backflow through outfalls. HEC-RAS 2D or MIKE would capture these.

## Front ends

- **Trace view:** a web page with a split screen. On the left, a live agent log with hand-offs and provenance chips; on the right, Google Photorealistic 3D Tiles (or the DEM mesh) with the water surface rising as agents finish.
- **Waterline AR:** an ARCore Geospatial (VPS) anchor at the site, with Streetscape Geometry for occlusion and a translucent plane at P50 depth plus a P10–P90 band. Toggles: storm / king tide / both.
